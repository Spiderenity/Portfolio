# 일러스트 제작·재생성

2026-11-18 복구. 현재 게시된 6개 그림용 실행 진입점은 `rebuild.py`다.
원본은 WORK/포트폴리오에 보존하며 실행 위치와 무관하게 찾는다. Python과 Pillow가 필요하다.

```powershell
python -m pip install -r tools/illustration/requirements.txt
python tools/illustration/rebuild.py 2
python tools/illustration/rebuild.py 4 --source "../포트폴리오/1 (8).png"
```

기본 출력은 `tools/illustration/output`이다. 해당 번호 한 장만 만들며 게시 파일을 덮어쓰지 않는다.
결과를 확인한 뒤 `--publish-assets`를 붙이면 해당 웹용 이미지에 저장한다.
사이트 게시에는 별도로 Git 커밋·푸시가 필요하다.

`sticker.py`는 `a060876:refine_assets.py`에서 이미지 처리 부분을 추출했다.
1·2·3·5번은 당시 `prepare_media.py`의 1800px 제한·WebP quality=88 단계를 거쳐 스티커를 만든다.
4번은 이번 교체 때와 같이 PNG 원본을 직접 사용한다. 랜덤 시드는 기존과 같은 `170+번호`다.
원본의 외곽에 연결된 밝은 배경만 제거하고, 28px 여백·31px 최대 필터·미세 불규칙 테두리·내부 구멍 채움을 적용한다.

흰 우표를 만들었던 최종 코드 자체는 Git에 남아 있지 않았다.
6번은 현재 게시 파일에서 추출한 `stamp-white-06-alpha.png`로 우표 외곽을 정확히 보존하고,
원본 그림에 45px 흰 여백을 붙여 재구성한다. 크기가 바뀌면 자동으로 늘리지 않고 중단한다.
다른 비율로 바꿀 때는 프레임을 명시적으로 수정해야 한다.

`history/`의 세 파일은 커밋 `a060876`에서 바이트 그대로 복구한 과거 원문이다.
이 파일들은 참고·제작 과정 보존용이며 직접 실행하지 않는다. 오래된 영상 변환, 폰트 문서 수정,
페이지 수정 및 QA 출력까지 들어 있으므로 현재 실행 진입점으로 쓰면 안 된다.
`finish_visuals.py`는 이전 크림색 우표 코드이며 현재 흰 우표의 코드와 구분한다.
게시에서 빠진 그림과 과거 우표도 원본·기존 웹 파일을 그대로 보존한다.

기존 `tools/make-illustration-04.py`도 4번 단독 재생성용으로 유지한다.
이 코드·원본 대응표·테두리 입력은 제작 자료이므로 임시 로그로 취급해 삭제하지 않는다.

검증: 6장 모두 별도 폴더로 재생성해 크기가 현재 파일과 같은 것을 확인했다.
4번은 픽셀까지 동일했다. 과거 파일은 손실 WebP 인코딩·축소 환경의 차이가 있을 수 있어
픽셀 단위 완전 복원을 보장하지 않는다. 3번은 부드러운 외곽 알파에도 작은 차이가 있었다.
비교 수치는 `verification.json`에 기록했다. 게시된 파일은 변경하지 않았다.
